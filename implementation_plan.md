# Implementation Plan

[Overview]
This plan outlines the development of a "Salesforce Security Assessment" tool within Cline, focusing on key security aspects of Salesforce metadata and configuration. The goal is to enhance the existing `cline-audit-framework.js` to specifically automate data collection via Salesforce CLI for security-relevant metadata, implement detailed evaluation logic for the identified security categories, and generate comprehensive, security-focused reports. This implementation will provide a streamlined and integrated security audit experience directly within the development environment.

[Types]
The type system changes will involve refining the structure of the `auditResults` object within the `SalesforceWellArchitectedAudit` class to accurately store collected Salesforce security metadata and query results, as well as detailed evaluation scores and recommendations specifically for each of the defined security categories. The `evaluationFramework` will be significantly simplified to focus solely on security-related criteria.

[Files]
File modifications will primarily focus on enhancing the core audit framework and generating new report outputs, all with a security-centric focus.

- New files to be created:
    - `config/security-evaluation-config.json`: This file will store customizable parameters for the security audit, including scoring thresholds and specific security criteria weights.
    - `reports/security-audit-report.md`: The detailed markdown report generated by the security audit.
    - `reports/security-audit-report.html`: The visual HTML report with charts and metrics generated by the security audit.
    - `reports/security-action-plan.json`: A JSON file containing prioritized security recommendations and timelines.
    - `reports/security-compliance-summary.json`: A JSON file summarizing security compliance status.
- Existing files to be modified:
    - `src/evaluation/cline-audit-framework.js`: This is the primary file for all core logic implementation, including Salesforce CLI integration for security data, detailed security evaluation, and security report generation.

[Functions]
Function modifications will involve implementing placeholder methods and enhancing existing ones to support full security audit functionality.

- New functions:
    - A utility function or class (e.g., `executeSfCliCommand`) within `src/evaluation/cline-audit-framework.js` or a new helper file to encapsulate `child_process` execution of Salesforce CLI commands.
- Modified functions in `src/evaluation/cline-audit-framework.js`:
    - `constructor()`: Modify to load and parse `config/security-evaluation-config.json`.
    - `initializeFramework()`: Update to dynamically configure *only* the security evaluation criteria and weights based on `config/security-evaluation-config.json`. The framework will be simplified to reflect the 7 security categories.
    - `collectOrgData(orgUrl)`: Implement orchestration of Salesforce CLI commands to retrieve *only* necessary security-related metadata and query data.
    - `collectMetadata()`: Implement actual Salesforce CLI `sf project retrieve` commands for security-relevant metadata types (e.g., SecuritySettings, Profile, PermissionSet, SharingRules, Network, ConnectedApp, NamedCredential, CustomMetadataType). This will specifically include retrieving `ConnectedApp` metadata.
    - `collectSecuritySettings()`: Implement Salesforce CLI `sf data export` queries for user security data, permission set assignments, login history, and potentially custom object/field definitions related to data classification.
    - `evaluateAllPillars()`: This function will be refactored to focus solely on security evaluation, likely calling a single, new top-level security evaluation function. The `easy` and `adaptable` pillar evaluations will be removed or set to zero weight.
    - `evaluateTrustedPillar()`: This function will be renamed or refactored to `evaluateSecurityPillar()` and will orchestrate the evaluation of the 7 security categories.
    - `evaluateSecureSection()`, `evaluateCompliantSection()`, `evaluateReliableSection()`: These will be adapted or replaced by new functions corresponding to the 7 specific security categories (e.g., `evaluateProfilesAndPermissionSets()` which will now include connected apps and their data access levels, `evaluateObjectAndFieldSecurity()`, `evaluateSharingAndVisibility()`, `evaluateCustomCodeAndAPI()`, `evaluatePublicAccessSettings()`, `evaluateDataClassification()`, `evaluateAuditTrailsAndMonitoring()`). Each will parse collected data against defined criteria and assign scores.
    - `calculateOverallScore()`: Update to reflect the new security-focused scoring model (likely 100% weight on the security pillar).
    - `generateRecommendations()`: Implement logic to analyze security scores, categorize recommendations (critical, high, medium, low), and populate `auditResults.recommendations` with security-specific advice.
    - `generateMarkdownReport()`: Implement comprehensive markdown report generation, including overall security score, breakdown by security category, detailed recommendations, and action plan.
    - `generateHTMLReport()`: Implement HTML report generation for security, including structure for charts and visualizations of security posture.
    - `generateActionPlan()`: Implement logic to create a prioritized action plan for security improvements.
    - `formatRecommendations()`: Implement detailed formatting of security recommendations for inclusion in reports.
    - `formatActionPlan()`: Implement detailed formatting of the security action plan for inclusion in reports.
    - `collectPerformanceMetrics()` and `analyzeArchitecture()`: These methods will be removed as they are not directly relevant to a pure security assessment.

[Classes]
No new classes are planned. The existing `SalesforceWellArchitectedAudit` class in `src/evaluation/cline-audit-framework.js` will be extensively modified and refocused to encapsulate all new security assessment functionalities.

[Dependencies]
The primary new dependency will remain the `child_process` module (built-in to Node.js) for executing Salesforce CLI commands. No external `npm` package dependencies are strictly required for the core functionality, but a client-side charting library (e.g., Chart.js) might be considered for the HTML report's visualizations if complex charts are desired beyond basic HTML rendering for security metrics.

[Testing]
The testing approach will involve both unit and integration tests, with a strong focus on security.
- Unit tests: Focus on verifying the correctness of the evaluation logic for each of the 7 security categories, ensuring scores are calculated accurately based on various input data scenarios. Also, test the security report generation formatting.
- Integration tests: Verify the end-to-end flow, including successful execution of Salesforce CLI commands for security data collection, proper parsing of collected security data, and accurate generation of all security report types (`.md`, `.html`, `.json`).

[Implementation Order]
The implementation will proceed in a logical sequence to minimize dependencies and facilitate incremental development, with a clear focus on security.

1.  Create `config/security-evaluation-config.json` with initial customizable security audit parameters, defining the 7 security categories and their weights.
2.  Modify `SalesforceWellArchitectedAudit` constructor and `initializeFramework` to load and utilize `config/security-evaluation-config.json` and simplify the framework to only include security criteria.
3.  Implement a utility function/class for executing Salesforce CLI commands using Node.js `child_process`.
4.  Refine `collectOrgData` to orchestrate calls to *only* security-relevant data collection methods.
5.  Implement `collectMetadata` and `collectSecuritySettings` methods in `src/evaluation/cline-audit-framework.js` to retrieve *only* the metadata and query data relevant to the 7 security categories. Remove `collectPerformanceMetrics` and `analyzeArchitecture`.
6.  Refactor `evaluateAllPillars()` to focus solely on security, and implement new evaluation functions for each of the 7 security categories (e.g., `evaluateProfilesAndPermissionSets()`, `evaluateObjectAndFieldSecurity()`, etc.), parsing collected data against the defined security criteria and assigning scores.
7.  Update `calculateOverallScore()` to reflect the new security-focused scoring model.
8.  Implement `generateRecommendations` to categorize and format security recommendations.
9.  Implement `generateActionPlan` to create a prioritized security action plan.
10. Implement `generateMarkdownReport` to produce the detailed security markdown report.
11. Implement `generateHTMLReport` to produce the visual security HTML report.
12. Implement `formatRecommendations` and `formatActionPlan` for security report generation.
13. Develop unit tests for the security evaluation logic and report generation functions.
14. Develop integration tests to verify SF CLI command execution for security data and the complete security audit flow.
